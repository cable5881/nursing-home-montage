# 工作台入口、任务与验收

## 选择入口

只在实际制作、重做或继续视频时进入此流程。规则迭代、代码维护、版本检查不启动页面。已由队列派发的单视频子 Agent 按自己的 PROMPT 执行，不重复启动入口。

工作台随当前安装的 skill 分发，不复制进每个任务的冻结引擎。若从冻结引擎恢复，使用宿主登记的当前安装 skill 启动工作台；渲染仍使用原冻结引擎，不能从冻结快照启动网页入口。

所有路径基于当前安装的 skill 实际目录，PROJECT 是用户项目根，不能以 skill 安装目录作为项目根。Codex 与 WorkBuddy 使用相同 Python 标准库服务、同一个本地 FIFO；不另索取大模型 Key，也不启动未登录的宿主 CLI。

以下示例在安装 rtk 时使用此前缀，未安装时移除 rtk。默认执行并打开用户电脑的系统默认浏览器（如 Chrome、Safari、Edge）：

```bash
rtk python3 SKILL/scripts/workbench.py --project PROJECT --host workbuddy
# Codex 调试时将 host 改为 codex
```

已运行的同项目服务会复用；代码变化且没有未回收执行者时更新 HTTP；存在执行锁时复用健康服务并返回 deferredUpgrade，不自动打断制作。只绑定 127.0.0.1，页面凭据仍留项目私有配置。macOS 同时在项目根留下 `打开视频工作台.command`，以后双击即可独立打开，不需要 Agent 对话；它固定项目与安装入口，复用服务并遵守执行锁保护。不同浏览器不共享会话，首次使用完整 URL 建立本地会话；只输入裸端口地址时显示连接指引，不暴露访问令牌或取消认证。浏览、配置、成品查看不要求 Agent 在线，新制作仍需要协调者。把返回的完整 URL 提供给用户。启动脚本通过系统默认浏览器打开；Codex、WorkBuddy 均不额外创建 Agent 内置浏览器或侧栏工作台页。若自动打开失败，提供项目启动器和完整 URL，让用户在本机浏览器打开，不回退到 Agent 内置页面。工作台页面检查也使用用户电脑的本地浏览器；无页面模式和维护模式仍不自动打开浏览器。

WorkBuddy 首次启动可能返回 `needsHostService=true`，此时按返回的 [宿主后台服务](workbench-hosts.md) 用 WorkBuddy 原生后台模式启动服务，再原样重试入口；智能体自行完成，不要求用户执行命令。服务必须在宿主命令返回后仍能读取项目文件，才能报告启动成功。

主对话随后读取 `scripts/workbench/AGENT.md`，通过[原生文件通道](workbench-channel.md)和当前宿主原生子 Agent 工具协调；新批次先做[整批统一策划](batch-planning.md)，逐视频用连续执行器推进。没有原生子 Agent 能力时说明具体限制并保留排队任务，不冒称已开始。长素材、稿件、日志留在单条工程和子 Agent，主对话只收短结果。

## 从对话提交制作

用户已经给足资料时，不要求其在页面再填一遍。智能体把本次请求写入项目 `.montage/workbench/submissions/` 下的新 JSON，再执行入口 `--request FILE`。同一次请求重试沿用该文件和 `--invocation ID`，新请求用新 ID；脚本原子记录批次，避免重复入队。

请求常用字段：`source`（机构目录）或 `institutionId`、`institutionName`、`person`、`count`、`requirements`、`facts`、`music`、`videoPreferences`。多人物用 `people:[{"id":"人物ID","count":2}]`；总数和各人物顺序由脚本展开。人物 ID 读项目配置，不猜测。source 首次导入机构资料库，任务固定版本；同机构后续更新不改变旧任务。

缺少配置时先打开页面，引导用户补缺，不丢弃本次请求，也不自行填入虚假服务凭据。

## 用户明确不要页面

用户说“本地执行这个视频任务”“直接执行”“不用页面”或“不要 HTTP”时，按无需页面处理，不要求用户重复说明，使用：

```bash
rtk python3 SKILL/scripts/workbench.py --project PROJECT --host workbuddy --mode direct --request FILE
```

此模式不启动 HTTP、不打开浏览器，仍在同一本地 FIFO 保存状态、按原提交顺序执行；已有工作台服务不强制关闭。当前宿主按同一 AGENT.md 协调与回传，用户可在对话查看真实阶段，之后打开页面仍能看到记录。`--mode maintenance` 不启动服务、任务或监听，仅供明确的维护入口。

执行者已回收后，运行 `python3 SKILL/scripts/workbench/deliver.py --project PROJECT TASK_ID` 获取 MP4、PNG、三文件发布 ZIP 的实际路径，直接交付脚本返回的发布包；不把引擎内部含编辑 HTML 的包另行交给用户。此命令也不启动 HTTP。

## 状态

草稿 → 排队中 → 制作中 → 待验收 → 已验收。待补充、失败或中断暂停在原序号；取消需要确认执行者退出。制作完成的队列终态与用户验收分开记录，验收不会占用制作锁，也不会更改领取顺序。列表、详情都有验收入口，部分完成且其余已取消时可验收已经完成的条目。

工作台任务只需在任务页答复一次。页面会显示答复已保存、正在等待旧执行者结束或等待重新接单。主 Agent 在线时会按原序号重新派发；若主对话已停止接单，用任务页的连接指令恢复原对话即可读取已保存的答复。

## 验收与清理

用户先预览成品，在列表或详情点击“验收成品”即记录用户验收并提交后台清理，不再弹窗或二次确认。页面显示后台清理状态，成品可继续查看和下载；清理失败保留已验收状态及成品，提供“重试清理”。服务重启后恢复未完成清理，不因旧进程尚活着而重复执行。制作 Agent 不能代替用户点击验收。

只清理任务自己创建的 `PROJECT/作品/工作台_ID`、对应封面编辑缓存，以及能按不可变素材 ID 恢复的任务素材副本。保留全部已完成版本的 MP4、PNG、三文件发布 ZIP、发布文案及最少计划、核验与验收记录。原始机构资料库、人物、配置、认可基线、其他任务与共享引擎不属于清理范围。路径或成品哈希有变化、执行者未回收、重做仍引用工程时拒绝清理。

验收后中间配音、数字人和渲染资产已删除；再改口播时新建任务，从原资料版本完整重做，不伪称还能无成本恢复。封面自包含数据仍保留，可继续编辑首帧；成功更新后重新待验收。验收本任务不等于更新项目的通用样式基线。

无页面模式或用户在对话要求验收时：

```bash
rtk python3 SKILL/scripts/workbench/accept.py --project PROJECT preview TASK_ID
rtk python3 SKILL/scripts/workbench/accept.py --project PROJECT accept TASK_ID --token PREVIEW_TOKEN --confirmed
```

先呈现真实预览；只有用户明确验收并接受清理范围后才用 `--confirmed`。预览令牌绑定本次文件清单，变化后必须重新预览。清理中断不撤销用户的验收，成品仍保留；可从页面重试清理。CLI 的显式预览令牌仍校验文件变化。

## 进度与内容管理

阶段进度、回传间隔、删除任务保留成品与批量管理见[工作台进度与管理](workbench-management.md)。删除任务会先独立保留成品，再清理任务数据并移除任务记录；验收则保留任务状态。两者均保护原始文件与认可基线。
