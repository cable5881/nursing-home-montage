# 批次执行

所有新批次使用 references/workbench.md 的同一本地 FIFO；无页面制作使用相同入口 --mode direct。不从旧 batch.py 启动另一套并行引擎。

批次先由一个原生策划子 Agent 统一理解素材、提炼共同事实、编写并复核各条计划，再逐视频派发全新原生子 Agent。具体交接和差异矩阵见 [统一策划](batch-planning.md)。各篇默认完整覆盖共同核心，只有用户明确要求时制作专题。

确定性步骤与供应商任务轮询交给连续执行器，内容和画面审核由对应子 Agent 执行；主对话仅保留索引和短结果。每条独立保存工程、阶段、供应商任务ID和失败信息。只用一个 FIFO，同时最多一条执行，失败或状态不明不越过队首。

旧 batch.py prepare/start/run/status 命令保留为兼容入口：prepare 可准备素材与计划文件；start/run 将批次幂等登记到同一队列并返回主 Agent 指引，不再使用 max_active 并行渲染。已经产生配音或数字人资产的旧批次保留计划及冻结引擎，按原工程检查点导入，原目录保留；新批次进入统一策划。旧已登记批次的审核改由当前视频子 Agent 使用 pipeline review 完成。

共享事实、文本和媒体索引按内容复用；配音、数字人和抠像只在输入及配置匹配时复用。复用资产复制到本工程，不引用可能被其他任务验收删除的文件。验收只释放本任务引用，无其他任务使用的对应媒体缓存才删除；共享依赖环境与小型素材索引保留。

成品仍包括 MP4、PNG 和发布文案。每条执行正常身份、内容、原片、实际渲染和发布包核验。只完成部分时如实显示，不把程序校验或部分完成当作用户验收。
