# WorkBuddy 执行服务

默认使用 WorkBuddy 原生命令工具的官方后台模式启动 HTTP。入口返回 needsHostService=true 和 serverCommand 后，由主 Agent 执行该命令并保存实际后台句柄；等待服务就绪，再原样重试入口，保持 request 和 invocation。健康的 host 服务直接复用，不强制切成独立系统服务。此流程无需启动 Terminal，也不依赖 Codex。

只有 /api/health 正常、项目文件能读取，且启动工具返回后台句柄后后续命令仍能连接，才报告服务已启动。启动命令只运行服务；重试入口统一尝试打开用户系统默认浏览器，避免重复打开两个页面。浏览器打开与 HTTP 启动分别报告；系统没有打开浏览器时提供完整 URL，不创建 Agent 内置页面。

服务在宿主官方后台会话中连续执行固定阶段。host/standalone 表示进程的管理方式，不是允许制作与否的权限开关。host 调用保留目标脚本声明的 uv/Python 环境和已有目录 mkdir 兼容处理；其余宿主权限保持不变。禁止清除安全环境变量、非沙箱标志、自行分离进程或复制凭据绕过宿主限制。

命令代理或后台会话实际报错时保留工程、云端任务 ID 与队列锁，恢复原生后台会话后从原阶段继续；有未知运行者时不重启或释放执行锁。WorkBuddy 关闭后不承诺宿主后台服务持续运行，下次入口按实际健康状态恢复。

项目的打开视频工作台.command 仍是用户从本机系统会话独立打开页面的可选入口，不作为 WorkBuddy 自动启动 HTTP 的必经步骤。工作台代码均保存在 skill 中。

接单细节见 workbench-channel.md。页面连接、主 Agent 能领取、子 Agent 有进度、执行服务能运行分别核对；重试不等于生成成功，没有活跃协调者时不能宣称已恢复接单。
