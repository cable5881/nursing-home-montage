# 整批素材与统一策划

新批次先派发一个策划子 Agent；其真实退出并通过校验前，不派发任何视频。策划与逐视频 Agent 都由主 Agent 直接创建，不相互派生。详细事实与正文留文件，主对话仅收短摘要和路径。

1. 读取 inputs.json，确认人物顺序、每人数量、共同偏好、单条偏好与固定素材。通过原生文件通道 prepare-planning 建立一次共享素材索引。相同文件按内容命中缓存，新增或改变文件单独分析。
2. 实际检查本批素材，按 narration.md 提炼共同核心。默认各篇都是完整机构介绍，改变切入、结构、表达与镜头组合；不把共同核心分割成互不完整的专题。用户明确要求专题时才按其原话授权制作。
3. 在 plans/0001.json 等文件写正常 plan-schema.md 格式的完整逐条计划，人物与配乐按固定输入。每条正常计划中的事实引用、文案、分镜、封面及发布文案均需完整。
4. 写 draft.json，绑定 inputs.json 的 fingerprint：

```json
{"inputFingerprint":"实际指纹","coreFacts":[{"id":"f1","text":"共同事实原意","evidence":{"source":"介绍.txt","quote":"可在该索引文档中找到的原文片段"}}],"items":[{"index":0,"person":"实际人物ID","plan":"plans/0001.json","mode":"comprehensive","openingAngle":"本条切入","structure":"本条叙述结构","coverAngle":"封面兑现的正文承诺","factCoverage":["f1"]}],"review":{"facts":"具体事实复核结论","differences":"具体差异复核结论","preferences":"具体偏好适配说明"}}
```

index 从0开始，只用于内部映射；网页按第1条等显示。items 覆盖本批全部视频；共同事实 id 也用于各条正常计划及口播 factIds，覆盖关系必须实际体现在口播引用中。专题使用 mode=topic、topicAuthorization=用户明确要求的原句，必须能在共同或对应单条偏好中找到。

5. 原生文件通道 planning-check 对全部计划执行正常结构校验，并核对人物、数量、来源、共同事实覆盖、差异矩阵及完全重复稿件。它不能替代你的内容判断。修正错误后重新校验。
6. 校验后生成 approved.json，绑定输入、草稿和所有计划的文件哈希。之后 report completed 并结束。视频子 Agent 只读自己的批准计划与共享索引，继续完成内容审核、原片和成片检查，不重复起一套文案。

材料或偏好变化导致指纹不同，旧批准失效。已执行视频的计划需要修改时另存单条重做，不重写正在执行的整批。旧冻结批次已产生付费资产时保留原计划和引擎，从原检查点导入统一队列；不能为了补策划而重做付费资产。
